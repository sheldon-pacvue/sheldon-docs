# Agent Hub · 实现现状（诚实盘点）

#agent-hub

> 目标愿景见 [[agent-hub/产品定位]]。本文描述 **0.0.1 代码里实际有什么、缺什么**，避免把「启动器」误解成「已能从零搭好环境」。

## 结论（先说）

**目前启动器尚未打通「环境扫描 → 安装/配置 → 一键可跑」的基本闭环。**

| 用户期望 | 0.0.1 现实 |
|----------|------------|
| 扫一遍机器上有哪些 Agent、缺什么运行时/凭据 | ❌ 未做到整机环境扫描 |
| 从启动器里安装并配好可工作环境 | ❌ 未做到；安装能力极窄且未进桌面 |
| 已有 Run Context 时一键 `run` | ⚠️ 部分做到（需事先手写 YAML 或 adopt） |

0.0.1 更像是：**在已纳管、已配好 YAML 的前提下**，提供 list / run / uninstall 与桌面门户——而不是完整的「环境工厂」。

---

## 环境扫描：缺什么

### 已有（但不算「环境扫描」）

`agent-hub scan` 实现的是 **v1 安装前体检**，不是 v2 设计里的「整机 Agent 环境盘点」：

| 检查项 | 说明 |
|--------|------|
| Node / npm / 磁盘 / 代理 / 注册表 | 通用前置条件 |
| `openclaw` / `hermes` detect | 仅两个内置目标是否在 PATH |
| profile 占位 | 占位检查 |

**没有**：

- 扫描 npm global / brew / pipx 等装过的 Agent 包列表
- 扫 PATH / 典型足迹目录做孤儿发现（设计文档 §8 弱信号的大部分能力）
- 校验某 Agent 的 Run Context 是否「可启动」（runtime 可满足、secret 可解析、skill 路径存在）——这部分只在 `config --check` / `run` 时单点触发，**不是** `scan` 的统一报告
- 桌面应用中的「扫描」入口或结果页

### 已有（弱信号 / 列表）

`agent-hub list`（`composeInventory` + `detect: true`）会：

- 列出 **已纳管**（`~/.agent-hub/agents/*.yaml`）的 Agent
- 对 **openclaw / hermes** 及 **声明式 yaml adapter** 做 `detect.command` 探测 → 标记为 `detected`

**局限**：

- 内置安装器目标仅 `openclaw`、`hermes`（`BUILTIN_INSTALLER_TARGET_IDS`）
- 弱信号**不会**自动写 Run Context，也不会提示缺哪些 env/skill
- 准确度与覆盖面远低于产品设计中的 Inventory 引擎

## 安装：缺什么

### 已有（极窄）

```bash
agent-hub install openclaw|hermes|all [--dry-run] [--yes]
```

- 通过内置 Adapter 执行 **npm 全局安装** + 版本探测
- `--dry-run` 输出 `INSTALL_PLAN`
- 装完后需用户自行维护 Run Context（或配合 `adopt`，但 adopt 同样只支持 openclaw / hermes）

**没有**：

- 安装时自动写入完整 Run Context（runtime / env / workspace / skills）
- 安装 Node 运行时、mise/nvm、系统依赖
- 引导配置 Secret / API Key
- 声明式 adapter 的 `install` 块真正执行（多数仅 detect）
- **桌面启动器内**的安装向导、扫描结果联动

### 与「完整运行环境」的差距

产品设计里一次 `run` 需要的环境层（见 [[agent-hub/产品定位]]）：

| 层次 | 0.0.1 |
|------|-------|
| 运行时切换 | ✅ `run` 时委托 mise/nvm 等（若 YAML 已配） |
| Secret / env | ✅ 解析（若 YAML 已配） |
| workspace / skill / mcp | ✅ 挂载（若 YAML 已配） |
| **从零生成上述配置** | ❌ 无引导、无扫描补缺 |

即：**能跑的前提是「你已经会写 YAML 或手动装完再 adopt」**，启动器不负责把环境补齐。

## 人机交互启动器：实际边界

| 能力 | CLI | 桌面 0.0.1 |
|------|-----|------------|
| 门户列表（portal snapshot） | ✅ `list` | ✅ 瓦片 |
| 启动 Agent | ✅ `run` | ⚠️ 依赖已有配置，无「一键装完再跑」 |
| 编辑 / 校验 Run Context | ✅ `config` | ✅ YAML 抽屉 |
| 卸载 | ✅ | ✅ 卸载向导 |
| **环境扫描** | ⚠️ 仅 `scan` 体检，非环境盘点 | ❌ |
| **安装 Agent** | ⚠️ 仅 openclaw/hermes | ❌ |

## 当前可用的真实路径

适合今天能走通的流程（开发者向）：

1. **手动**安装 Agent（npm/curl/等）
2. `agent-hub adopt openclaw`（或 hermes）— 写入基础 Run Context
3. **手动编辑** `~/.agent-hub/agents/<id>.yaml` 补 runtime、env、skill
4. `agent-hub config <id> --check` → `agent-hub run <id>`
5. 或用桌面改 YAML、再在外部终端 `run`

**不能**指望：打开桌面 → 扫描 → 安装 → 自动可跑。

## 待补齐（基本闭环，建议优先级）

面向「启动器」最小可用故事，建议按序：

1. **环境扫描（MVP）**
   - `scan` 扩展：对已纳管 Agent 跑 `config --check` 聚合报告
   - `list --detect` 增强：足迹路径存在性 + 缺失项摘要
   - 桌面：「扫描环境」按钮 + 问题列表

2. **安装/纳管（MVP）**
   - `install` 后自动落盘**最小可跑** Run Context 模板
   - adopt 支持声明式 adapter id
   - 桌面：「添加 Agent」向导（选 adapter → install/adopt → 缺项清单）

3. **配置引导**
   - 交互式补 secret（env 名 + keychain 引用）、workspace 默认值
   - 扫描结果 → 一键跳转编辑对应 YAML 字段

4. **与设计文档对齐**
   - 弱信号：npm/brew/pip 枚举（[[agent-hub/设计/产品设计 v2]] §8）
   - 整机 `scan` 与 Inventory 合并叙事

详细里程碑仍见 [[agent-hub/设计/任务拆分 v2]]，但需接受 **M2/M3 在「扫描/安装」维度的完成度低于文档标题**。
