# Agent Hub · 产品定位

#agent-hub

## 一句话（目标）

> **agent-hub 要做的是：能直接开工的 Agent 运行环境 + 方便选用与切换的人机交互启动器。**

安装、盘点、卸载是支撑能力；重心是 **Run Context 描述下的完整环境**，经 `run` 或桌面门户启动。

> [!warning] 与 0.0.1 现实的差距
> **基本的环境扫描和安装闭环尚未做到。** 详见 [[agent-hub/实现现状]]。当前可用的是：在**已纳管且 YAML 已配好**时 list / run / uninstall；`scan`/`install` 仅为窄范围、偏 v1 体检与 openclaw/hermes 安装，**桌面无扫描/安装入口**。

## 完整运行环境包含什么（目标模型）

| 层次 | 内容 |
|------|------|
| 运行时 | Node / Python 等，委托 mise、nvm、pyenv |
| 凭据与环境 | API Key、代理等（Secret 解析） |
| 工作区 | `workspace` |
| 能力扩展 | Skill、MCP 挂载 |
| 入口 | `entry` spawn |
| 状态 | Run Context + inventory |

见 [[agent-hub/数据与存储]]。

## 人机交互启动器（目标）

| 形态 | 目标体验 |
|------|----------|
| CLI / TUI | 扫描 → 补缺 → `run` 一条链 |
| Mac 桌面 | 门户选 Agent、向导安装、YAML 校验 |
| `run --shell` | 已配好的 subshell |

TUI 方向见 [[agent-hub/设计/UI 设计稿索引]]。

## 与「仅安装」的边界

| 我们做的 | 我们不做的 |
|----------|------------|
| 编排运行时、包管理器、Secret | 替代 mise / npm / brew |
| 维护可运行环境配置 | 只保证二进制在 PATH |
| 统一启动入口 | 替代各 Agent 自带 UI |

## 能力矩阵：目标 vs 0.0.1

| 能力 | 目标 | 0.0.1 实际 |
|------|------|------------|
| 完整环境 `run` | ✅ | ⚠️ 依赖事先写好 Run Context |
| CLI 门户 list/inspect | ✅ | ✅ |
| 桌面门户 + YAML + 卸载 | ✅ | ✅ 无扫描/安装 |
| **整机 / Agent 环境扫描** | ✅ | ❌ `scan` 仅为安装前体检；弱信号极窄 |
| **安装并配好环境** | ✅ | ❌ 仅 openclaw/hermes npm 安装；无环境引导 |
| 安全 uninstall | ✅ | ✅（npm-global 自动执行有限） |
| adopt 纳管 | ✅ | ⚠️ 仅 openclaw / hermes |
